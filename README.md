# ガラポンチャレンジ

会員ポイントを使った「その場でガラガラ抽選」を、スマホ1画面で完結させるWebアプリです。
サーバー不要・単一HTMLファイルなので、GitHub Pagesにそのまま置いて使えます。

## 想定の運用フロー

出張型サービスのため、お客様と対面するのは常にキャストのみで、
店舗スタッフは現場に同行しません。その前提で以下の流れを想定しています。

1. お客様が予約時または現場で「〇回チャレンジする」と申告（例: 1000pt = 1回）
2. キャストが、このページを自分のスマホで開く（QRコードで受け取る）
3. 開始前に、予約名（必須）を入力し、回数をセットする
4. 申告された回数をこの画面にセットし、キャストがお客様の目の前で1回ずつ回す
5. 当選結果は画面に表示されるので、それをキャストがその場で確認
6. 全回終了後に表示される「結果を送信」ボタンをキャストがタップすると、
   スプレッドシートへの記録＋店舗スタッフへのメール通知が自動で行われる
7. 当たった特典は「本日から」または「次回から」使えるものとしてお客様にご案内

**系列店舗・担当キャストの選択は、一度選ぶとそのスマホに自動で記憶されます。**
次のお客様の際にアプリを開き直しても、同じ店舗・キャストが選択された状態から
始まります（変更したい場合はプルダウンから選び直せばOKです）。
一方で、予約名・当選結果は毎回リセットされ、記憶されません（プライバシー保護のため）。

**このページのURLはお客様には共有しない運用を想定しています。**
お客様の目の前ではキャストのスマホ画面を見せるだけで、URL自体は伝えない形です。

## ポイントの扱いについて

このアプリ自体はポイント残高を管理・自動消費しません。
「1回あたり〇〇pt」という目安を画面に表示するだけで、実際のポイント消費は
既存の会員管理・レジ運用側で、キャストからの事後報告をもとにスタッフが
手動処理する想定です。（お客様の実際のポイント残高とは連動していません）

## 結果の自動送信について

キャストが「結果を送信」ボタンを押すと、Googleスプレッドシートへの記録と
指定メールアドレスへの自動通知が同時に行われます。第三者の外部サービスは使わず、
お店専用のGoogleアカウント内だけで完結する仕組みです。

### セットアップ手順（初回のみ）

1. **お店専用のGoogleアカウントを用意する**（個人のプライベートなアカウントとは
   別にすることを強くおすすめします）
2. そのアカウントで新しい **Googleスプレッドシート** を1つ作成する
3. メニューから **拡張機能 → Apps Script** を開く
4. 表示されたエディタの中身を全て削除し、このリポジトリの
   `apps-script/Code.gs` の内容をそのまま貼り付ける
5. コード上部の `NOTIFY_EMAIL` を、通知を受け取りたいメールアドレスに書き換える
   ```js
   const NOTIFY_EMAIL = "your-email@example.com";
   ```
6. 画面右上の **デプロイ → 新しいデプロイ** をクリック
7. 種類の選択で **ウェブアプリ** を選ぶ
8. 「次のユーザーとして実行」= **自分**、「アクセスできるユーザー」= **全員** に設定して
   **デプロイ** をクリック（初回は権限の承認を求められるので許可する）
9. 発行された **ウェブアプリのURL**（`https://script.google.com/macros/s/.../exec` の形式）
   をコピーする
10. `index.html` の `CONFIG.notifyEndpoint` に、そのURLを貼り付ける
    ```js
    notifyEndpoint: "https://script.google.com/macros/s/xxxxx/exec",
    ```

これで、キャストが「結果を送信」を押すたびに、スプレッドシートに1行ずつ結果が
記録され、同時に指定したメールアドレスへ通知メールが届くようになります。

### 注意点

- `CONFIG.notifyEndpoint` を空文字のままにしておくと、「結果を送信」ボタン自体が
  表示されません（この機能を使わない場合はそのままでOKです）。
- ウェブアプリのURLは「アクセスできるユーザー: 全員」で公開する必要がありますが、
  URLを知らない限り第三者がアクセスすることはできません。ページURLと同様、
  外部に漏らさないようにしてください。
- 送信結果はブラウザの通信環境に依存します。通信エラー時は画面にエラーメッセージが
  表示されるので、電波の良い場所で再度お試しください。
- スプレッドシート・通知メールには、予約名や当選内容が記録されます。
  取り扱いには十分ご注意ください。
- すでにこの仕組みを使い始めていて、シートに「送信日時・店舗名・お客様名・挑戦回数・結果詳細」
  の5列で記録が溜まっている場合、`Code.gs` の更新により列が
  「送信日時・店舗名・**キャスト名**・お客様名・挑戦回数・結果詳細」の6列に変わります。
  古い行とヘッダーがズレるので、スプレッドシート側で「キャスト名」列を
  お客様名の左に1列挿入し、ヘッダーの文言を手動で直しておくことをおすすめします。
- さらにその後の更新で、「結果詳細」の1列にまとめて記録する方式から、
  「1回目結果・2回目結果…」と回数ごとに列を分ける方式に変わりました。
  各セルの中身は**ランク名のみ**（例: `残念賞`、`2等`）というシンプルな表記です。
  賞の内容（何をプレゼントするか）や有効期限は、スプレッドシートには載らず、
  通知メールの方にまとめて記載されます（スタッフが対応する際はメールを参照してください）。
  この変更を反映した場合も、既存のシートの列がズレるので、
  「結果詳細」列を削除し、「1回目結果」以降の列を手動で追加してから
  Code.gsを差し替えることをおすすめします。
  `Code.gs` 内の `MAX_DRAW_COLUMNS`（初期値10）は、`index.html` の
  `CONFIG.maxDraws` と同じ数にしておくと過不足がありません。

## カスタマイズ方法

`index.html` を開き、`<script>` タグ内の `CONFIG` オブジェクトを書き換えるだけで
店舗ごとの内容に変更できます。系列店が複数ある場合は `shops` に店舗を追加すれば、
画面に系列店の選択プルダウンが自動で表示されます（1店舗だけの場合はプルダウンは
自動で隠れます）。

```js
const CONFIG = {
  pointsPerDraw: 1000,       // 1回あたりの目安ポイント（表示のみ）
  maxDraws: 10,              // 1回のチャレンジで選べる最大回数

  // 共通の送信先。店舗ごとに送信先を分けたい場合は、下の shops 側の
  // notifyEndpoint に個別設定すれば、そちらが優先されます。
  notifyEndpoint: "",

  // 系列店舗の一覧。1店舗だけの場合も配列に1件入れてください。
  shops: [
    {
      name: "〇〇店",
      castNames: ["山田", "佐藤", "鈴木"],  // キャスト名プルダウンに出す一覧
      notifyEndpoint: ""                     // 空なら↑の共通 notifyEndpoint を使用
    },
    {
      name: "△△店",
      castNames: ["田中", "高橋", "伊藤"],
      notifyEndpoint: ""
    }
  ],

  prizes: [
    {
      tier: "jackpot",       // 'jackpot' / 'win' / 'small' / 'miss' の4種類
      label: "1等",          // 画面・スプレッドシートに出るランク名
      prize: "本指名料 無料券", // 景品名（通知メールにのみ表示されます）
      validity: "本日からご利用いただけます", // 有効期限の説明（通知メールにのみ表示されます）
      weight: 2               // 当選しやすさ（重み。数値が大きいほど出やすい）
    },
    // ...他の景品も同じ形式で追加・編集できます
  ]
};
```

- `weight` の合計に対する比率で当選確率が決まります。
  例）2 : 8 : 25 : 65 の場合、1等は 2 ÷ 100 ＝ 2% の確率です。
- `castNames` は、キャストの入れ替わりに合わせてここに名前を追加・削除してください
  （フリー入力ではなくプルダウン選択にしているのは、入力の手間を減らすためです）。
- 系列店ごとに記録先のスプレッドシートを分けたい場合は、店舗の数だけ
  「結果の自動送信について」の手順を繰り返してスプレッドシートとApps Scriptを作成し、
  それぞれの `notifyEndpoint` に発行されたURLを設定してください。
  1つのスプレッドシートに全店舗まとめたい場合は、共通の `notifyEndpoint` だけ設定すればOKです
  （送信データに店舗名の列があるので、あとから店舗ごとに絞り込めます）。
- 景品は何個でも追加できます（tier は上記4種類から選んでください。見た目の色が変わります）。

## GitHub Pagesでの公開方法

1. このフォルダの中身（`index.html` と `assets` フォルダ。`apps-script/Code.gs` は
   公開ページには含めず、Apps Scriptのエディタに貼り付けるためだけのファイルです）を
   リポジトリにアップロード
2. リポジトリの **Settings → Pages** を開く
3. **Branch** を `main`（または公開したいブランチ）に設定して保存
4. しばらくすると `https://ユーザー名.github.io/リポジトリ名/` でアクセス可能になります
5. そのURLをQRコードにして、キャスト用のスマホやカードに印刷して配布してください
   （お客様には直接教えない運用推奨）

## ローカルでの確認方法

ブラウザで `index.html` を直接開くだけで動作します（インターネット接続はGoogle Fontsの
読み込みにのみ使用、なくても代替フォントで動作します）。

## 注意事項

- 本アプリは抽選演出のみを提供するものです。景品交換・ポイント精算などの
  実運用は店舗側の既存フローに沿って行ってください。
- 表示される確率（`weight`）は一例です。実際の景品原価や運用ルールに合わせて調整してください。
- お客様ごとに、キャストが「次のお客様へ（リセット）」ボタンで画面をリセットしてからご利用ください。
